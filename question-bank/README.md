# V2：以连续用户场景测评 SEC 财报 Agent

制作及核验日期：2026-09-22。正式题库 8 份，每份只对应一家公司的 5 个连续问题，共 40 题。公司、场景和入口见 [CATALOG.md](CATALOG.md)。

## 本版的三项约束

1. **一家公司一个 set**：MU、STX、WDC、SNDK、NTAP、PSTG、RMBS、MRAM 各 5 题。覆盖内存、硬盘、闪存、企业存储、内存接口/IP 和 MRAM；不把八家公司视为完全相同的商业模式。
2. **真正使用前题结果**：每个 set 一个 `scenario_id`。第 2–5 题均消费紧邻前题的至少一项输出，也可引用更早步骤；明确的 `input_bindings` 记录用了哪道题的哪个字段。不是仅把五道独立题排在同一文件。
3. **hops 有可复算依据**：每题保存证据、计算和判断的依赖图，`hops` 由该图计算，详细定义与全部拆解见 [HOPS.md](HOPS.md)。

## 与原示例保持一致的正式格式

`sets/` 中每份文件均为含 5 个对象的 JSON 数组，每个对象恰好具有以下 16 个字段：

`id`, `question`, `type`, `answer`, `scenario_id`, `workflow_step`, `total_steps`, `hops`, `xbrl_concepts`, `filing_type`, `filing_period`, `answer_type`, `tool_required`, `source`, `reasoning`, `evidence`。

三个步骤/跳数字段为整数，`xbrl_concepts` 为字符串数组，其余字段为字符串。组内 `workflow_step` 依次为 1–5，`total_steps` 恒为 5。依赖图及其他新增元数据放入 `grading/`，不改变正式示例结构。

`answer` 保持字符串类型，内容是 JSON 格式的真实标准答案对象；数字用十进制字符串保存，逻辑值和缺失值用 `true`/`false`/`null`。`answer_type` 使用示例已有的 `numeric_value`、`calculated_value`、`text_summary`。

`type` 保留 SEC/XBRL Retrieval/Computation 四类名称。连续任务会在同一文件中穿插读取、运算及判断，不能再按“纯检索文件/纯计算文件”切断场景。`tool_required` 描述所需能力，不强制绑定未验证的 SDK。

## 场景执行方式

- **同一公司五题按顺序、在同一上下文中执行**，保留前面得到的事实、输入数值和必要的未舍入中间结果。切换公司才开启新上下文。
- 仅向被测 Agent 提供 `agent/` 中对应题目；不要开放 `sets/`、`grading/`、答案历史、验证输出或整个含答案的工作区。
- 无答案视图包含场景编号、步骤、依赖及固定申报日期，便于连续运行；这是派生视图，不声称自身也采用正式 16 字段格式。
- 工具可使用浏览器、HTTP、SEC API 或 XBRL 解析器。记录实际工具调用次数和耗时，但不能把它们直接等同于基准 `hops`。
- SEC 请求失败单独记录为基础设施失败，不直接解释为财务理解错误。本版没有运行任何被测 Agent。

建议同时记录两种结果：

| 模式 | 上下文输入 | 用途 |
|---|---|---|
| 端到端场景 | Agent 自己在前题的输出 | 检查整条任务是否完成，以及早期错误如何传播 |
| 条件诊断 | 评测器注入前题的正确状态，再问当前题 | 定位当前步骤的检索、计算或口径错误 |

两种模式必须分开报告；不能在端到端运行中暗中纠正前题。条件诊断使用正确、未提前舍入的前题数值，且只注入此前步骤，不提供当前题的答案或证据。

## hops 的解释

本版采用本地明确定义的 `conditional_evidence_depth_v2`，不是声称行业存在统一的 hops 标准。

- 一处新证据读取、一个明确派生财务量、一项比较判断，各权重 1。
- 已有前题输出、题面用户假设、原值改名，各权重 0。
- 节点深度为自身权重加父节点的最大深度；本题取所有输出路径中的最大深度。
- 并行读取不累加；前题已经完成的工作不重复计算。题库采用保存的规范推导图，模型把计算压成一行代码不会改变基准值。

例如年度值已在前题中取得，而当前题需要读取九个月数据、相减反推 Q4、再计算 Q4 毛利率：最长路径是 1 → 2 → 3，因此 `hops=3`。具体每题为什么是 1、2、3、4 或 5，均可在 [HOPS.md](HOPS.md) 和 `grading/rubrics.json` 中复查。

## 来源与期间

所有证据来自 SEC EDGAR 的具体申报或附件，限定在指定历史版本。当前使用 25 个 SEC 页面（包括供附件追溯的父 8-K 页面）。

- `source`：具体申报/附件的 HTML 地址，并带 XBRL 数据点 ID 或匹配文字片段。
- `evidence`：列出表格、章节、上下文与其他必要数据点链接。
- `grading/sources.json`：记录 filing date、report date、accession、CIK 和下载内容的 SHA-256。
- `grading/rubrics.json`：记录原始数值、符号、scale、直接证据和前题输入绑定。

文件名和公司名按所引用历史申报记载，尤其 Pure Storage/PSTG 不作为当前名称或代码的断言。FY2024/FY2025 及 2025 年季度的财年日历按各公司报告处理，不强行当作同一自然年。

跨文件的题目，正式字段 `filing_type` 表示当前主要证据页的申报类型；完整所需文件在 `evidence` 和无答案视图 `document_scope` 中列出，不能据此误认为全题只用一个文件。

数值字段中的 USD million 已按 XBRL scale 从 USD thousand 或 USD million 归一化。正文文字片段自动高亮取决于浏览器支持，但其匹配文本已在对应文件中核对，地址始终指向具体 SEC 文件而非首页。

## 评分与精度

每题 5 分，40 题合计 200 分：答案 2 分、SEC 证据 1 分、期间/单位/口径 1 分、前题使用及方法 1 分。具体答案、容差、输入与公式见 `grading/rubrics.json`。

- 多字段答案的 2 分按字段数均分；数值应按指定单位及绝对容差检查。
- 来源取数按披露精度保存；计算货币值通常保留三位小数（百万美元单位），百分比、百分点和倍数保留两位。每字段容差单独记录。
- **只在最终展示时舍入**。跨题保留原始金额与未舍入比例，否则可能产生 0.01 个百分点的误差。评分端根据 `input_bindings` 和 `derivations` 可重建精确状态。
- 文本接受语义等价与正常大小写差异；日期按 ISO 日期规范化。明确缺失的 GAAP 指引必须返回 null，不能以零、非 GAAP 指标或事后实际值替代。
- 后题使用了错误的前题结果时，端到端答案仍按标准答案计分；另标记“前题错误传播”。方法分可单独判断后题是否对其收到的输入执行了正确逻辑。

压力比例、覆盖倍数、平均季度节奏等用户假设都在题干中标明，并以 `assumption` 节点记录。它们不是 SEC 披露、公司预测或投资建议。Rambus 的 billings 不作为 GAAP royalties；Sandisk 的单项减值加回不称为公司完整非 GAAP 利润。

本版关注连续任务完成能力，不据此声称具有未见样本泛化能力。若以后划分训练集和测试集，应按公司/完整场景划分，不拆散五步或把同一份报告随机分到两侧。

## 复用与校验

前版四家公司的 SEC 来源、取数成果及 14 道题的可复用素材已经沿用，并调整为相互依赖的五步流程；新增四家公司的资料单独核对。旧的四公司双文件分组已替换，不在正式题库中混留旧版。

```bash
python3 tools/validate_question_bank.py
```

默认离线检查 8×5 数量、单一公司、原示例字段类型、所有前题字段绑定、规范图深度、计算与判断结果、证据 URL 和无答案视图。若有本次下载的 SEC HTML 缓存，可用 `--source-cache /path/to/cache` 额外验证文件 SHA-256 及实际定位点。
